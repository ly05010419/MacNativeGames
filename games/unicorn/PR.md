## Summary

新增亚洲版《圣兽之王》1.05 的 macOS ARM64 原生移植。本体、累计更新和两个 DLC 从玩家自己的文件构建。

```text
games/unicorn/
├── scripts/       容器提取、完整性检查、更新合并、运行表生成
├── third_party/   Bayonetta 3 基线的独立改写器与 NVN/Metal 副本
├── runtime/       两模块加载、HLE、输入、存档与音频
├── app/           引用本地工作目录的 macOS 启动器
└── assets/        已验证版本的哈希，未包含游戏数据
```

基线为 MacNativeGames `30a1b93` 中的 `games/by3`，审查分支已同步至上游 `a988b5e`。
独立副本是项目对其他游戏要求的布局；不修改 TOTK/BotW/Bayonetta 3 的运行文件。
大部分新增行来自该独立副本；建议优先审查下面列出的适配点，而不是将整个副本当成新写的运行层。

| 必要改动 | 具体问题与行为 |
|---|---|
| 加载器/内存 | main、sdk 两模块；BSS 栈映射；SDK 弱分配器服从 main 强定义，保持分配和释放一致 |
| HLE | 游戏实际请求的文件系统初始化、随机数及 DLC 编号查询；DLC 必须从用户输入验证 |
| 音频 | Nintendo Opus 多流包和六声道解码，调用宿主 libopus |
| 图形 | QUADS/TRIANGLE_FAN 转 Metal 三角形；64 KiB 对齐的客体 GPU 地址与 CPU 存储分离，保留池容量 |
| 构建 | 亚洲版 1.05 的固定哈希、BKTR 更新合并、两个授权 DLC；原始 NSZ 可先本地转换 |
| 探针 | 为分阶段绑定补齐模拟程序 control 元数据，保留未翻译状态和原检查 |

没有添加游戏逻辑修改。已移除 BY3 专用的分辨率/补丁生成脚本和 `BY3_PATCHES` 装载入口，
其余继承的可选功能不代表本游戏具备对应帧率、画质或宽屏补丁。

## Evidence

- **Before:** 项目没有本游戏的构建入口；独立适配时曾出现启动黑屏、分配器不一致和 GPU 池对齐耗尽。
  **After:** 本地 1.05 已显示中文开场、战场及交战后的 WIN 画面；独立 profile 手动保存后，退出并以新进程读档恢复同一战场。对应改动有内存、GPU 地址及六声道探针。详见 [VALIDATION.md](VALIDATION.md)。
- **Before:** CPU `probe-gfx` 在预测探针的 `control+0x714` 读取退出 139。
  **After:** 相同命令通过；24/26/27 三个语义负对照仍拒绝错误行为。
- 从原始 NSP 的新工作目录构建通过；303 项根目录测试跳过 1 项，其余通过；App 严格签名检查通过。
- 仅验证 Mac。实际游玩和剩余限制以验证记录为准；游戏、截图、存档、缓存和密钥不随源码提交。

此 Draft 用于讨论新增游戏适配的接收范围与维护方式。当前只验证 Apple M5 / macOS 26.4 上的亚洲版 1.05，
未验证 iOS、完整游戏流程、DLC 纹章选择或长期热稳定性；未宣称稳定 60 FPS。

## Merge Danger

**Door:** two-way

新增目录和第三方声明可独立撤回。当前 App 引用工作目录，尚未集成根目录 `build_app.py`。

**Blast Radius:** Unicorn

仅本游戏的独立运行层、工具和许可登记。当前构建要求两个 DLC 和精确版本；不是通用 NSP/NSZ 运行底座。
温度检测为本地独立工具，不随此移植提交。未将 CPU 探针、标题或短时帧率当作完整流程与长期稳定性证明。
