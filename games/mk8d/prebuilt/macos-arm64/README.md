# Locked binary-only shader tooling

Two build-time tools from nxnative commit `062cd06e6fd79ec0bcd52d59f778fd6438994a2a`, byte-identical to the files there. `SHA256SUMS` covers the exact file set, and `scripts/build_mk8d.py` verifies it before staging. Neither tool is bundled in the generated game app, and neither holds translated game shaders.

- `dmsh_xlate/`: the 12 required files of nxnative's `dm/gfx/tools/dmsh_xlate_bin`, the framework-dependent .NET 10 shader translator (Maxwell shader → SPIR-V), with its apphost, runtime and dependency metadata and DLLs. `dmsh_xlate.pdb` and the Humanizer satellite resource folders are left out. Its source is not duplicated in this target: the translator source and its shader-only Ryujinx subset are in the [pinned nxnative tree](https://github.com/seedds/nxnative/tree/062cd06e6fd79ec0bcd52d59f778fd6438994a2a/dm/gfx/tools/dmsh_xlate), and the Ryujinx modification record is [ryujinx-build.md](../../third_party/licenses/ryujinx-build.md).
- `spirv_cross/`: only the license files of SPIRV-Cross. The SPIR-V → MSL converter itself is built at packaging by `scripts/build_mk8d.py` (`build_spirv_cross`) from SPIRV-Cross `vulkan-sdk-1.4.363.0` (commit `f11ba9f0b21ba8fc15153d50a2a1ae31ab1cf8f7`, fetched from GitHub and checked), with clang and no CMake; no binary is carried (2026-10-28, after PR #1226).

`runtime/gfx/tools/dmsh_chain.lock` pins the translator DLL fingerprints, the translator's embedded source hash (`--source-sha`) and SPIRV-Cross's `--revision` (its release and commit time, not its bytes, which differ between compilers); this target's `dmsh_chain.py` takes the source hash from the lock instead of hashing a source checkout. Updating either binary needs new full SHA-256 sums, its source provenance, a new lock, a regenerated `runtime/gfx/nvn/dmsh_chain.h` (`dmsh_chain.py --header`) and a full private shader and host rebuild. No tool is downloaded or rebuilt implicitly.

**Checked 2026-10-28 (after PR #1226).** The maintainers rebuilt `dmsh_xlate` from nxnative's source at `062cd06` (`dotnet build -c Release -r osx-arm64 --self-contained false`, .NET SDK 10.0.401): `--source-sha` gives the lock's value, the NuGet DLLs are byte-identical, and on the same 4,683 jobs (Tears of the Kingdom shaders) both builds write byte-identical SPIR-V and `.res.json` files. The files here stay upstream's bytes, so the lock and the chain version stay upstream's. The rebuilt DLLs have the same sizes and differ only in build-specific bytes: module IDs, PDB paths, the names the regex source generator derives from file paths, and version stamps (upstream's were built with a newer SDK and stamped with nxnative commit `2c31212`, ours with the pinned commit); the `dmsh_xlate` launcher is .NET's apphost (upstream's is universal, ours arm64).
